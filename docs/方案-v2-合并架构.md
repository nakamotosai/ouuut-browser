## 一、先解决「能不能合并」——三方二进制都不可改

这是整个方案的**硬约束**,必须先说清楚,否则后面全是空谈。

| 组件 | 许可证 | 能否改 / 能否派生 |
|---|---|---|
| CloakBrowser 包装层 | MIT | 能 |
| **CloakBrowser 二进制** | 专有(`BINARY-LICENSE.md`) | **不能**:禁止再分发、禁止派生、禁止逆向、要求 OEM/SaaS 授权 |
| ego lite harness(JS) | **MIT** | **能**:可复制、可改、可再许可、可出售 |
| **ego lite 浏览器本体** | 闭源,单独下载 | **不能**:服务条款明确禁止逆向、反编译、修改、派生;且禁止"用代理/VPN 伪装 IP 绕过使用限制" |
| Camoufox | **MPL-2.0** | 能,文件级 copyleft |
| ungoogled-chromium | BSD-3-Clause | 能 |

**结论:不存在"把两个二进制拼起来"的合法路径。** 唯一合法路径是:

```
自研 Chromium/Firefox 内核(fork 开源底座)
  + MIT 组件(ego 的 harness 设计,可直接复用代码)
  + MPL 组件(Camoufox 的思路,可合规借鉴)
  + 干净室重实现(CloakBrowser 的思路,只借想法不借代码)
```

这条约束反而**简化**了设计:我们不需要纠结"跟谁集成",只需要明确"从谁那里学什么"。

### 关于 ego lite 的逆向分析

ego lite 的服务条款明文禁止逆向工程。本项目的 REA 分析**仅用于理解接口与设计取舍**,
产出结论用于驱动我们自己内核的设计,**不复制其代码、不派生其作品、不打包其二进制**。
这是分析用途;真要商用,一律以"干净室重实现"为准。此条作为项目红线记录在案。

## 三、核心设计决策:一个抽象解决两个对立哲学

### 矛盾在哪

- **CloakBrowser 的哲学**:每次都是一个全新的假身份。用完即弃,不留痕。
- **ego lite 的哲学**:一个真实的人,agent 借用他的登录态。身份就是你自己。

两者看似互斥。**不能合并的原因是抽象层次错了** —— 它们不是两种产品,
而是**同一种东西的两种配置**。

### 解法:把「档案(Profile)」提升为一等公民

```
Profile = {
  id,                     # 稳定标识
  kind: real | persona | disposable,
  seed,                   # persona/disposable 由 seed 决定全部指纹
  fingerprint: {...},     # UA/平台/屏幕/GPU/字体/时区/语言/WebGL/Audio/WebRTC
  proxy,                  # 该档案绑定的出口
  storage: {...},         # cookie / localStorage / 历史,随档案持久化
  gesture_model,          # 行为模型
  lifecycle: persistent | ephemeral,
}
```

三种 `kind` 走**完全相同**的内核、通道、校验、harness,**唯一差别是身份从哪来**:

| kind | 身份来源 | 典型用途 |
|---|---|---|
| `real` | 从系统 Chrome 一次性导入(含扩展) | 日常浏览、agent 借用我的登录态 |
| `persona` | seed 生成自洽画像,持久化并缓慢演化 | 长期养号、需要稳定身份的自动化 |
| `disposable` | seed 生成,用完即销毁 | 一次性抓取、隔离测试 |

**同一个浏览器进程里可以同时开着三种档案**:`real` 用于我自己浏览,
`persona` 用于需要稳定身份的 agent 任务,`disposable` 用于高风险的一次性任务。

这就同时拿到了 ego 的「人机共用」和 Cloak 的「隐身多开」,而且不冲突 ——
因为它们是**同一抽象的三个实例**,不是两套系统硬凑在一起。

### 硬要求:档案隔离必须真的隔离

ego lite 的 `Space` 号称隔离,但 **cookie 跨 Space 可读**:官方自带文档自述「该 profile 的 cookie jar 与 HTTP 缓存与你自己的标签页、以及其他所有任务空间共享」【官方】,独立第三方实验与维护者回复见 `证据-R1-ego-lite网络调研.md` R4 #319。
ouuut 的档案隔离必须是**硬隔离**:

- cookie / localStorage / IndexedDB / Cache 按档案分目录
- agent 的脚本只能拿到本档案的 handle,拿不到其他档案的
- 禁止从脚本发起非本档案出口的网络请求(ego 的 #315 就是 prompt injection → 原始 CDP → 偷 HttpOnly cookie)

### 各层从谁那里学什么

| 层 | 学谁 | 学什么 | 合法性 |
|---|---|---|---|
| 通道层 | ego lite | ⚠️ **本行原表述已被 REA 推翻,保留以示轨迹**。原表述:「它**确实在用 CDP**(元素操作是 native CDP input),传输层未验证 —— 所以只借『不暴露端口』,不借『不用 CDP』」。**REA 结论(B1/B2)**:主通道确为 **Mojo/ipcz 私有 IPC**(不是 CDP over TCP),CDP 是按需子通道,**且未发现自动化路径自动发送 `Runtime.enable`** → 借「进程内通道 + 不发该命令」这个形状,见 (REA 结论,**已移出仓库**,见 ADR-010) | 借设计,不抄代码 |
| 通道层 | rebrowser | `Runtime.enable` 泄漏的三种修法(`addBinding` / `alwaysIsolated` / `enableDisable`)、栈帧与世界观名的随机化 | MIT / 公开研究 |
| 内核层 | CloakBrowser | C++ 源码级补丁是唯一站得住的隐身层;JS 注入会被 `nativeTampering` 抓到 | 只借想法 |
| 内核层 | fingerprint-chromium | ungoogled 基底 + `--fingerprint-*` 一族开关的可组合设计 | 开源补丁 |
| 内核层 | ego lite | **原生快照**:在内核里造语义快照,而不是往页面注入 JS。这是它真正原创的部分,也是"agent 友好 + 不被检测"能同时成立的关键 | 借设计 |
| 运行时 | CloakBrowser | geoip 与出口对齐、humanize 的起点 | 只借想法 |
| 运行时 | Camoufox | 一致性问题域与路径(用相对路径而非绝对路径表达平台差异) | MPL-2.0 |
| harness | ego lite | JS 批处理、`@N` 引用 + `loc=` 选择器、任务空间生命周期与所有权交接、site-learnings manifest | **MIT,可直接复用** |

## 五、三阶段落地(每阶段都能独立交付)

### 阶段 A:能跑通(不追求隐身)

- 内核:`ungoogled-chromium` 构建流水线跑通(Linux CI + Windows 构建)
- 通道:先用 CDP + rebrowser 式双端补丁,**先把 `Runtime.enable` 按住**
- 运行时:档案引擎(三种 kind)+ 硬隔离 + 一致性校验器
- harness:移植/重实现 ego 的 MIT harness 思路(我们自己写,可参考)
- 验收:检测基准台(附录 A §A6)上有分数矩阵,且 `bot-detector.rebrowser.net` 的 CDP 项全绿

### 阶段 B:自研通道

> ⚠️ **本节降为条件性**:是否要做自研协议,取决于 M0 判定「不发 `Runtime.enable` 是否已足够」。
> 若足够则本节取消(省 4–6 周,改投档案引擎与服务器化)。判据见 `方案-v3-终稿.md` §四 A2。

- 用 Mojo/IPC 之类的**非 CDP 通道**做导航/点击/输入/取文本/快照
- CDP 只作为逃生口存在,默认不启用、不自动启用
- 验收:抓包证明自动化全程没有 `Runtime.enable`

### 阶段 C:身份与行为

- persona 演化(字体慢慢装、历史慢慢长)
- 内容驱动的行为引擎(停留时间与内容长度相关)
- 验收:100 个 seed 无一矛盾;行为分布通过统计检验

## 八、红线(写进项目门规)

1. **不打包、不派生、不逆向复制任何第三方二进制**(Cloak / ego 均适用)。
2. **不做自动过验证码**。ego 自己都写明不绕过 CAPTCHA;我们同样不碰。
3. **不做金融/医疗/政务认证系统的未授权访问**。AUP 明文禁止。
4. **不夸大能力**:封号是多因素决策(IP 段、支付、行为、账号年龄),指纹只是其中一环,
   文档必须写清,避免用户把所有封号归咎于工具。
5. **零遥测 + 可复现构建**:这是本项目相对 Cloak 与 ego 唯一不可让渡的差异点。
   ego 的隐私政策与其"无数据收集"宣传不符(默认开启崩溃上报、带设备标识的用量分析),
   这正是我们要打的位置。
