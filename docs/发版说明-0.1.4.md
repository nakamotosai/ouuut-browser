# ouuut 0.1.4 发版说明

> 状态:**已发布**(2026-10-26)。仓库已公开:https://github.com/nakamotosai/ouuut-browser

## 这是什么

一个自带 Chromium 的 agent 浏览器:把「开页面、点、填表、取快照」变成脚本里的几行调用,
每个页面归属于一个 **TaskSpace**,退出时不留孤儿页。

## 这一版改了什么

0.1.4 与 0.1.3 的**浏览器本体完全相同**(604/611 个文件逐字节一致)。差异只有 native 层的 7 个 JS 文件:

| 文件 | 变化 |
|---|---|
| `js/native/binding/egress-guard.mjs` | 出口闸:防止本机代理被非预期用途借用 |
| `js/native/binding/rotation.mjs` | 轮换改为**档案级租约**(ADR-013,仅生产用途) |
| `js/native/binding/release.mjs` | 发布包校验路径 |
| `js/native/bin/launch-args.mjs` | 启动参数拼装 |
| `js/native/bin/ouuut.mjs` | 入口 |
| `js/native/binding/session.mjs` | 会话绑定 |
| `js/native/serve/boot.mjs` | 服务启动 |

也就是说:**这不是浏览器升级,是发布/安全层的一次收紧。**

## 安装

```bat
node tools/install-release.mjs ^
  --package dist\updates\0.1.4 ^
  --dir "F:\apps\ouuut-browser\0.1.4" ^
  --pubkey release\ouuut-release.pub.pem
```

安装器会**先验签、再逐文件校验、最后一次性换名**;任何一步不符就整体不落地。

## 签名密钥已轮换(重要)

旧私钥随系统重装丢失,本次重新生成:

- 新公钥指纹(SHA-256,SPKI):`0d041b07d2d780b85902013a72622137257e6d20a6809cc167e8a2dc499fa032`
- 公钥:`release/ouuut-release.pub.pem`(已替换)
- 私钥:仓库外的私有目录,**不入库、不进包**
- **后果**:0.1.3 的包是用旧密钥签的,用新公钥校验会失败。目前无外部用户,故代价为零;
  若 0.1.3 曾分发给任何人,必须让对方改走 0.1.4。

## 已知限制

1. **R1 异路径冷重建未完成** —— 源码侧全部通过(取源、依赖同步、三个补丁 `cleanly`、`gn gen`),
   但两次 `gn gen` 因**工具链解析路径大小写不同**产出了不同的模块表,导致模块编译失败。
   结论:现有 `REPRODUCIBILITY.json` 只钉了 MSVC/SDK 版本号,**没有钉工具链路径集合**,不足以让第三方复现。
   ⇒ **本版不声称"可复现"**;记录格式补全后会重新基线。
2. **更新源不对外开放** —— 自动更新只服务自用通道,第三方请按下文「安装」自行构建/安装。
3. **签名密钥于 0.1.4 轮换** —— 0.1.3 的包用旧密钥签,新公钥验不过;0.1.3 未对外分发,无影响。
