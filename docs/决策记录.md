## ADR-001 · 许可证 = Apache-2.0

- **日期**:2026-10-24(**用户拍板**)
- **决策**:本项目自有代码采用 **Apache License 2.0**。

  fork 的 MIT harness 需保留 MIT 文本与版权行。新增依赖受 `docs/法律红线.md` L2 白名单约束。

## ADR-006 · 内核版本策略:滚动跟随 stable,不做 LTS

- **日期**:2026-10-24
- **决策**:内核基线取 **ungoogled-chromium 当前 stable tag**,滚动跟随(约 4 周一版);
  **不做 LTS**;**绝不靠改 UA 假装新版本**(UA 版本号必须 = 内核真实版本)。
- **理由**:
  1. 真实 Chrome 自动更新,**版本陈旧本身就是判别特征**。实测:CloakBrowser 免费档
     UA 报 `Chrome/146.0.0.0`,而 2026-10-24 真实 Chrome stable = **157.0.8103.15**
     (chromiumdash 官方接口)—— **落后 11 个大版本**。见竞品缺点表 C9。
  2. 伪造 UA 版本会与**特性检测**对不上,比版本旧更糟。
- **影响**:**F2(一条命令 rebase)从「维护卫生」升级为「反检测能力」**,
  列为 M1 第一优先级。跟版成本是永久性的,这是本项目最大的长期工程负担。
- **细化(2026-10-24,M0 实测补充)**:
  > **「绝不伪造 UA 版本」与「必须伪装成 Google Chrome 品牌」是两件事。**
  >
  > - **版本号必须真实** —— 必须等于内核真版本,否则特性检测对不上
  > - **品牌必须像 Chrome** —— 检测方的基线就是 Google Chrome;Google Chrome 不出现在
  >   `navigator.userAgentData.brands` 里就是一项红(见 `docs/M0-结论.md` §2.2)
  >
  > 参考形态:ego lite 报 `{Chromium: 154.0.8037.44}` + `{Google Chrome: 154.0.8037.44}`
  > —— **版本真实、品牌伪装**。这一项归 M1 的内核补丁。
- **状态**:已定

## ADR-011 · 检测基准的方法是「同机同代理对照」,不是绝对分数

- **日期**:2026-10-24
- **决策**:M0 与后续所有检测基准,一律采用**同机、同代理、同时间窗**的
  **对照矩阵**(裸 Playwright / rebrowser 补丁 / CloakBrowser / ego lite / ouuut),
  而不是只报「我们拿了 X 分」。
- **理由**:绝对分数受网络、代理、检测站版本、时间影响极大,不可复现、不可比。
  对照矩阵能把「工具差异」从「环境噪声」里分离出来 —— 这正是我们要回答的问题
  (「按住 `Runtime.enable` 是否已足够」是一个**差分**问题)。
- **影响**:`probe/` 下的脚本必须支持对同一目标批量跑多个被测对象,并同轮输出矩阵。
  出口固定性由 **ADR-013** 另行规定。
- **状态**:已定

## ADR-012 · M0 判定:F17 从「自研协议栈」降级为「驱动层补丁 + 参数白名单」

- **日期**:2026-10-24 · **依据 M0 实测**(证据 `probe/out/20261024-020902/matrix.json`,
  结论 `docs/M0-结论.md`)
- **背景**:ADR-003 / ADR-005 把 4–6 周的自研通道(F17)悬置,判据是
  「按住 `Runtime.enable` 是否已足够」。

- **实测结果**(`bot-detector.rebrowser.net`,同机同出口,无头):

  | target | 红 | 黄 | 通过 |
  |---|---|---|---|
  | `pw-naive`(协议脏/参数脏) | 6 | 2 | 8 |
  | `patchright`(只修协议) | 3 | 2 | 11 |
  | `pw-hardened`(只修参数) | 3 | 0 | 13 |
  | **`patchright-hardened`(两者都修)** | **2** | **0** | **14** |
  | `cloak`(商业对照,含内核补丁) | 1 | 2 | 12 |

- **判定**:
  1. **「按住 `Runtime.enable` 不够」** —— 修完它之后仍有 3 红。
  2. **「只修启动参数也不够」** —— 参数全干净时 `runtimeEnableLeak` 照样红。
     → **两个变量正交,都必要**。
  3. **但都不需要「自研进程内 IPC 协议栈」**:协议净 + 参数净把红项从 **6 压到 2**,
     **一行内核代码都没有**。
     ⚠️ **不能简单说「已优于商业方案」**:实测 cloak 的 `storagePartitioning` 因内核 146
     而**未评分**(它的分母是 15),同分母 15 项下 `cloak` 是 **1 红 2 黄**、
     `patchright-hardened` 是 **2 红 0 黄** —— 各有胜负。
     **但红项性质不同**:cloak 的红项是**启动参数层、零成本可修**;
     我们的红项是**内核层** —— 那正是 M1 本来就要做的。见 `docs/M0-结论.md` §1.1。
  4. 剩余 2 红(`useragent` / `headless`)是**内核品牌与无头标识**,归 **M1** ——
     那是本来就规划好的主战场,不是额外成本。

- **决策**:
  - **F17 范围收窄**:4–6 周自研协议栈 → **≤1 周**的「驱动层按住副作用命令 + 启动参数白名单」
  - **不直接使用 patchright**:检测报错文本已**点名 Patchright**(见 `docs/M0-结论.md` §2.4),
    用它等于用一个有名字的签名。**抄做法,自己实现。**
  - **省下的时间全部投给 M1(内核构建)**
  - M4 的验收标准改写为 `docs/M0-结论.md` §2.3 那张「修复责任分工表」

- **影响**:
  - `docs/功能范围.md` 的 F17 描述需同步(已改)
  - M4 工期从「2–6 周(取决于 M0)」改为 **≤1 周**
  - **M1 的战略地位上升**:剩余红项只有内核能修

- **状态**:已定

## ADR-013 · 出网必须固定出口;resin 轮换池禁用于对照

- **日期**:2026-10-24 · **依据 M0 实测**
- **决策**:
  1. 任何「对照类」测量(检测基准、竞品对比、回归)必须走**固定出口**
  2. **resin 轮换池禁用于对照** —— 实测连续 8 次请求换 8 个出口 IP
  3. 固定出口用**单个 `bind-socks5` 节点**(`socks5://198.51.100.7:41105` 这类,无需认证,
     实测 30/35 存活且出口 STICKY),或本机直连
- **理由**:页面加载期会打开多个连接;若出口在轮换,一次访问就会暴露多个 IP ——
  既是巨大噪声(结论不可复现),也是巨大破绽(比任何指纹都显眼)。
- **影响**:`probe/` 的 `EGRESSES` 只登记固定出口;新增出口必须先在
  `probe/tools/scan_pinned_egress.py` 里验过 STICKY。
- **状态**:已定

## ADR-014 · WebRTC 必须显式抑制(我方当前缺口)

- **日期**:2026-10-24 · **依据 M0 实测**(`probe/out/20261024-021046/matrix.json`)
- **发现**:`browserleaks.com/webrtc` 上,**我方候选(`pw-naive` / `patchright-hardened`)
  泄漏 4 个公网候选**(两个 mDNS `.local`、一个全局 IPv6 `240f:77:160:1:…`、
  一个 IPv4 `124.211.130.95`);而 **CloakBrowser 返回 0 个候选 → 🟢**。
- **含义**:这是一条**我们差点漏掉的真实缺口**,且**不是协议层问题** ——
  CloakBrowser 用启动参数抑制了非代理 UDP(`--force-webrtc-ip-handling-policy`)。
- **决策**:M4 的修复清单里**必须包含 WebRTC 抑制**,并要求在**代理出口**下复测
  (直连时 WebRTC IP 与 HTTP 出口相同,暴露的是同一 IP;走代理时才构成真正的不一致泄漏)。
- **影响**:`docs/功能范围.md` F6(出口一致性自检)需要覆盖 WebRTC;
  M0 的多出口矩阵要把 `pin-jp-41105` 跑上。
- **落地(2026-10-25)**:启动参数已在 `native/bin/launch-args.mjs`;
  **验它生效**的部分在 `native/binding/webrtc-audit.mjs`(暴露为 `ouuut.auditWebrtc()`)。
  判据:**公网地址 = 泄漏**;mDNS `.local` = 缓解(不是泄漏,旧写法会误报);
  局域网地址 = 警告。ADR-014 记录的 4 条候选已复刻成固定用例。
- **状态**:已定 · **实现已落地**

## ADR-015 · ego lite harness 的 fork 点已落定(vendored,非 submodule)

- **日期**:2026-10-24 · **落地 ADR-004**
- **决策**:把 `citrolabs/ego-lite` **vendored 到 `harness/`**,固定在其
  commit `d392204d1ea1a8027a591ab2b0129c2e11d85f26`(MIT,CitroLabs 2026)。
  **不用 git submodule**,用 tarball 取 + 逐文件摘要记录。
- **为什么不用 submodule**:
  1. 我们**会改**这份代码(接通自写原生层),submodule 在这上面只会添麻烦
  2. tarball 取法给出**可独立校验的字节**(tarball sha256 + 逐文件 sha256 + tree digest)
     —— submodule 的校验依赖上游仓库仍然可达且历史未被改写
  3. 避开 `git checkout` 在共享工作区被策略拦截的问题
- **引入了什么**:`harness/` **197 个文件 / 4.83 MB**。
  校验入口:`harness/.vendored-manifest.json`。
- **排除了什么**:上游的 **agent 指令面**(`.agents/ .claude/ .claude-plugin/ .codex/
  .github/ AGENTS.md CONTRIBUTING.md .gitignore lefthook.yml`,12 个文件)。
  理由:放进本项目会形成**嵌套的 agent 配置**,可能被误当作本项目规则读进去 —— 那是污染。
  **功能代码一行未删**,排除清单记在 manifest 里。
- **最大收获(超出预期)**:`harness/docs/native-bindings-api.md`(24 KB)是
  **上游 JS harness 与其闭源原生层之间的接缝规格** —— 它列出了原生层必须注入的
  `globalThis.ego` 那组方法(18 个)。**这就是 M2/M4 自写原生层的实现契约形状**,
  外加三份配套要求文档(快照化简规则 / SDK 生命周期 / JS 对话框归属)。
  详见 `harness/README-ouuut.md` §三。
- **许可证义务(已完成)**:`harness/LICENSE` 保留原件;`LICENSES/ego-lite-MIT.txt` 存副本;
  `NOTICE` §3 改为实际归属(含 commit SHA 与可复算校验入口)。
- **纪律**:不追上游(ADR-004)。若将来更新这份副本,**必须同时**更新 manifest 的
  commit / tarball sha / tree digest / 排除表;若修改了 vendored 文件,须在 manifest 里
  增加 `local_modifications` 逐条登记 —— 否则「这份副本没被改过」就不可证了。
- **状态**:已定
