## 〇、一页结论

**做「可审计的、多身份的、能上服务器的隐身浏览器」。**

一句话差异化:**CloakBrowser 有隐身但没有身份和可信度;ego lite 有身份和 agent 界面但零隐身、
零隔离、上不了服务器。把两边的强项放进同一个「档案」抽象里,就得到市场上不存在的东西。**

最大的一个加速杠杆:**ego lite 的 harness 是 MIT 许可的**(19k star 的那个仓库),
可以直接 fork 复用它花了几个月做出来的 agent 界面;我们只写原生层(那部分是闭源、我们干净室重实现)。

## 二、ego lite 取证结论(证据来自本机实证,非推测)

### 2.1 可借的强项

| 强项 | 实证 | 怎么借 |
|---|---|---|
| **harness 是 MIT** | `citrolabs/ego-lite`,19,017 star,`LICENSE` = MIT | **直接 fork**。省掉几个月的 agent 界面工作 |
| **TaskSpace 模型** | `taskSpace(name,{profileId})` / `handOff()` / `finish({keep})`;状态落 `space-<id>.json` | 借设计;所有权(agent/user)与交接语义直接照搬思路 |
| **原生语义快照** | 内核生成纯文本 a11y 树,带 `@ref` / `loc=`,不注入页面 JS | 借设计(这是它最值钱的部分) |
| **进程内私有通道 + 不发 `Runtime.enable`** | [REA B1/B2] 主通道是 **Mojo/ipcz 私有 IPC**(`ego.mojom.EgoCliBridge` 等),CDP 只是按需子通道;`Runtime.enable` 在 `chrome.dll` **共 6 处(5 处 DevTools frontend/Node inspector 内部 + 1 处错误示例字符串)**,`chrome_elf.dll` 1 处,`ego-browser.exe`/`ego.exe` **0 处** → 常规 API 不依赖它 | **这是最值得抄的**:它证明「进程内通道 + 不发 `Runtime.enable`」可行。靶心因此收窄 —— 先证「不发 `Runtime.enable` 是否已足够」,再决定要不要自研协议(判据归 M0) |
| **原生 CDP 输入** | `Page.click ... with native CDP input` | 借设计 |
| **agent 光标 UX** | `kAgentCursorIcon` / `animationHighlightMouseToPosition` | 借设计(人机协作的可见性) |
| **Chrome 档案导入** | `ego-browser import --browser chrome` | 借设计 |

### 2.2 切入点(弱项)

**完整清单与逐条证据见 `竞品缺点-切入点对照.md`(唯一正本),本文件不复制。**
最决定方案形态的三条:

| # | 弱项 | 一句话 |
|---|---|---|
| **E8/E9** | **仅本机、仅 loopback、未暴露无头入口** | 【二进制】远程能力被官方主动移除(`EGO_AUTH_TOKEN` 等现在是启动错误),把自己锁死在桌面;CLI/SDK 无 headless 入口 → **服务器/无头是它最大的结构性空白** |
| **E4** | **遥测重,与「无数据收集」宣传矛盾** | 二进制内含 UMA 上传(`eventflow.citrolabs.ai/metrics`,带设备/用户 id 头)、Sentry 崩溃上传(运行进程命令行可见)、Langfuse(`us.cloud.langfuse.com`)、设备国家与时区上报 |
| **E2** | **档案不隔离** | 全机只有一个 profile【二进制】;官方自带文档自述 cookie 与用户自己的标签页及所有任务空间共享(自测数字 3478 个 cookie / 1161 域名,出自厂商文档)=【官方】;独立第三方复现见 R4 #319 |

### 2.3 一条反直觉的发现

ego lite 的 `navigator.webdriver === false` **不是隐身能力**,而是「它没打开自动化开关」的自然结果。
它把 `--enable-automation` 留在 stock 字符串里没启用 —— 这恰好说明:
**很多人以为的「隐身」其实只是「没触发显式标记」,真正的检测面在协议层和一致性层。**
这印证了我们把重点放在「协议层痕迹 + 一致性」上是对的 ——
但按 REA 的结论,**协议层要盯的具体是 `Runtime.enable` 这类会产生页面可观测副作用的命令,不是「CDP 整体」**(见 §2.1 与 `附录B-REA逆向结论.md` B2)。

## 四、四条关键架构决策

| # | 决策 | 理由 |
|---|---|---|
| **A1** | **fork ego 的 MIT harness,自写原生层** | 它花几个月做的 agent 界面(JS 批处理、`@ref`/`loc=` 选择器、TaskSpace 生命周期、site-learnings)是 MIT 的,直接复用;原生层(Mojo 通道、快照、CDP agent host)是我们干净室自己写的 —— 法律与工程双赢 |
| **A2** | **通道不暴露 TCP 调试端口,且不主动发 `Runtime.enable`** | [REA B1/B2] ego 的主通道是 Mojo/ipcz 私有 IPC(不是 CDP over TCP),且**未发现其自动化路径自动发送 `Runtime.enable`**。→ 靶心收窄为「不发 `Runtime.enable` 是否已足够过检测」,**这个判断归 M0**;若足够,阶段 B(自研协议)优先级下调,省下的 4–6 周改投档案引擎与服务器化 |
| **A3** | **档案(Profile)是一等公民** | 解决两家共同的空白:Cloak 只有一次性假身份、ego 只有单一真实身份。三种 kind 走同一内核同一抽象 |
| **A4** | **无头 / 服务器与桌面同等优先级** | ego 主动砍掉远程能力、锁定 loopback;Cloak 无头可用但没有身份管理 —— 这块是最大的市场空白 |

| 层级 | 内容 | 定价 |
