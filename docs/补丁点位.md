## 一、补丁 0001 · 去掉 UA 里的 `Headless` 前缀

**文件**:`components/embedder_support/user_agent_utils.cc`
**函数**:`GetUserAgentInternal()`(约 216 行起)

```cpp
std::string GetUserAgentInternal() {
  std::string product = GetProductAndVersion();
  if (base::CommandLine::ForCurrentProcess()->HasSwitch(kHeadless)) {
    product.insert(0, "Headless");        // ★ 这一句
  }
  ...
```

**要改成**:不再插 `Headless`(直接删掉这个 if,或改成受我们自己的开关控制)。

**为什么这一处能同时解决两个问题(重要)**:

| 现象 | 解释 |
|---|---|
| 主文档 UA 里出现 `HeadlessChrome` | 这一句插的 |
| **Web Worker 的 UA 也带 headless**(creepjs 实测,`docs/M0-结论.md` §1.3) | **worker 不走 CDP 的 `Emulation.setUserAgentOverride`** —— 驱动层的 UA 覆盖只作用于主文档,worker 的 UA 是原生算出来的。所以 `patchright-hardened` 用 `channel="chromium"` 修好了主文档(88%→38%)却修不掉 worker |

也就是说:**这一处补丁是唯一能覆盖 worker 的地方**。

## 二、补丁 0002 · 让 `userAgentData.brands` 里出现 `Google Chrome`

**文件**:`components/embedder_support/user_agent_utils.cc`
**函数**:`GetUserAgentBrandList()`(约 155 行起)

```cpp
std::optional<std::string> brand;
#if !BUILDFLAG(CHROMIUM_BRANDING)
  brand = version_info::GetProductName();   // ★ 只有 Chrome 品牌构建才加
#endif
```

之后这个 `brand` 会在 `GenerateBrandVersionList()`(约 506 行)里被追加进列表:

```cpp
blink::UserAgentBrandList brand_version_list = {std::move(greasey_bv),   // 例:Not:A-Brand
                                                std::move(chromium_bv)}; // Chromium
if (brand) { brand_version_list.emplace_back(brand.value(), version); }  // ★ Google Chrome
```

**要改成**:不管 `CHROMIUM_BRANDING` 与否,都把 `brand` 设成固定字面量 `"Google Chrome"`。

**为什么不用「构建时 `CHROMIUM_BRANDING=false`」**:那会连带动到图标、产品名等一大堆 Chrome 专属
资源(我们没有那套资源,而且改动面远超需要)。**只改这一个 `#if` 块,暴露面最小。**

**⚠️ 与 ADR-006 的关系**:我们**不伪造版本号**(`version` 始终取自
`version_info::GetVersionNumber()`,即内核真版本),只是把**品牌**改成 `Google Chrome`。
这正是 ego lite 的实测形态(`{Chromium,154.0.8037.44}` + `{Google Chrome,154.0.8037.44}`)。

## 三、不需要补丁的(启动参数层,零成本)

以下六项**都在启动参数里解决**,不要写进内核补丁 —— 写进去反而难维护:

| 项 | 做法 |
|---|---|
| `navigator.webdriver` | `--disable-blink-features=AutomationControlled` |
| `ipcFloodingProtection` | **去掉** `--disable-ipc-flooding-protection` |
| `popupBlocking` | **去掉** `--disable-popup-blocking` |
| `storagePartitioning` | 自己的 `--disable-features=`,不含 `ThirdPartyStoragePartitioning` |
| `viewport` | 按真实屏幕,不用 1280×720 默认值 |
| **WebRTC** | 抑制非代理 UDP(ADR-014);cloak 实测返回 0 个候选 |

以及 **WebGL**:不要带 `--enable-unsafe-swiftshader`(Playwright 无头时会自动加)。
若去掉后 WebGL 在服务器上不可用,那是**服务器模式**要单独处理的问题,不是桌面模式的补丁。

## 五、验收方式

补丁落位后,验收**不是**「编译过了」,而是:

1. `tools/20-rebase.sh` 一条命令跑通(含补丁应用)
2. `probe/run.py` 在 `bot-detector` 上:`useragent` 与 `headless` 两项由 🔴 转 🟢
   → 目标:**红项 2 → 0**,与 `ego` 的 16/16 持平
3. `probe/run.py` 在 `creepjs` 上:Headless 段等级应**降到 `ego` 同级(≤25%)**,
   且 `hasHeadlessWorkerUa` 由 true 转 false
4. **`window.chrome`** 可用 `probe` 的一条 `eval` 直接断言(`typeof window.chrome === 'object'`)

第 2、3 条是**可复算的量化验收** —— 它们就是 M1 的验收标准,不是「感觉好了」。
