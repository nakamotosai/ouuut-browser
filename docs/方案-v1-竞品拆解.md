## 〇、先修正一个前提

立项的理由是「CloakBrowser 漏洞很多,但星星很多」。这个前提**部分成立,但需要拆开看**:

1. **星星多 ≠ 技术强。** 它能火的主要原因是**零摩擦**:`pip install cloakbrowser`,
   把 `chromium.launch()` 换成 `launch()` 就能跑。同类有效方案过去全是付费 GUI 产品,
   没有一个能给脚本直接调用。
2. **它的漏洞不是「多」,是「集中」。** 真正致命的结构性缺陷只有一个:**它走 CDP**。
   其余(无一致性引擎、无身份持久化、行为层弱、闭源)都是可补的工程缺口。
3. **不要凭感觉打靶。** 在写第一行代码前,必须先做 M0 取证,用同一台机器、同一代理,
   把 CloakBrowser / 裸 Playwright / 打补丁版在公开检测站上的分数测出来。
   如果实测发现它的 CDP 问题已经被自己修掉了,整个差异化就得重设计。

## 一、CloakBrowser 体检表

### 1.1 已经做到的(实测)

| 能力 | 程度 | 证据 |
|---|---|---|
| C++ 源码级指纹补丁 | 强 | 官方称 87 个补丁,覆盖 canvas/WebGL/audio/fonts/GPU/screen/WebRTC/网络时序/CDP 输入 |
| 指纹参数化 | 强 | `--fingerprint-*` 全套 CLI 开关。实测 `timezone="America/New_York", locale="en-US"` 生效:探测结果由 `Asia/Tokyo`/`zh-CN` 变为 `America/New_York`/`en-US` |
| GPU 伪装 | 中上 | 实测两次启动返回不同 GPU 字符串(真实卡 vs 伪装值),说明按启动挑档案 |
| 地理一致性 | 中上 | `geoip=True` 把时区/语言/经纬度对齐到代理出口 IP |
| WebRTC 出口对齐 | 中上 | `--fingerprint-webrtc-ip=auto` 会解析代理出口 IP 并注入;缺 `socksio` 时静默降级并打印告警(实测已补装 `socksio` 修复) |
| 迁移成本 | 极低 | 与 Playwright API 同构,`stealth_args=True` 默认开 |
| 分发体验 | 强 | 自动下载二进制;Python / JS / .NET 三套 SDK;Docker 镜像 |
| 行为层 | 基础 | `humanize=True`,贝塞尔曲线 + 随机停顿 |
| 免费可用 | 是 | 免费档二进制 + 1 并发,无需 key(实测 `License: Free (no key)`) |

### 1.2 没做好或有结构性问题的

| 问题 | 严重度 | 说明与依据 |
|---|---|---|
| **仍然走 CDP** | 🔴 致命 | Playwright → CDP。`Runtime.enable` 泄漏是公开且被广泛使用的检测面(`rebrowser/rebrowser-patches` 专门为此而生,Cloudflare / DataDome 都在用)。它的补丁修的是「页面能看到的指纹」,修不了「协议层留下的痕迹」 |
| **没有一致性引擎** | 🟠 高 | 参数全靠调用方传,矛盾不管。实测:改时区/语言后,屏幕分辨率仍是 `1920×1080` 未跟随,`navigator.languages` 是否同步也未校验。UA 说 Windows、屏幕却是 Mac 分辨率这类矛盾,比「被识别成机器人」更容易被抓 |
| **没有身份持久化** | 🟠 高 | 无 persona / 档案概念,每次都是全新陌生人。真实用户有 cookie、历史、习惯;全新陌生人在风控里本身是负分 |
| **行为层是死算法** | 🟡 中 | 固定曲线,不读内容。读长文与读短讯停留时间相同,这是可测信号 |
| **二进制闭源** | 🟠 高(信任) | 它能看你全部流量。许可声明「无遥测,仅 license 校验 + 会话计数」,但无法审计 |
| **并发与许可限制** | 🟡 中 | 免费 1 并发;最新 major 需登录;条款禁止绕过会话限制。实测 4 进程并发未被本地拦截 → 限制是**条款级 + 服务端计数**,不是本地硬闸 |
| **无公开可复现基准** | 🟡 中 | 「通过 50+ 检测站」是营销话术,无可复现分数表 |
| **无自动化友好的会话编排** | 🟡 中 | 没有 TaskSpace 这类「人机共享登录态」的模型;它的定位是「一次性隐身会话」 |

### 1.3 一句话结论

它把**「指纹」这一层做到 85 分**,但把**「协议痕迹、身份、行为、可信度」留在 20 分**。

## 二、ouuut 浏览器定位

> **可审计的、无 CDP 的、多身份的隐身浏览器。**

三个支柱,对应 CloakBrowser 三个最大空缺:

### 支柱 1 · 不用 CDP(最大差异化)

Camoufox 已证明这条路可行:它用 Firefox 的 Juggler 协议,绕开整个 CDP 检测面。

- **阶段 A(快)**:CDP **双端**补丁。客户端不主动发 `Runtime.enable`(rebrowser-patches 思路),
  内核侧再补一层,让该命令「看起来从未发生」。
- **阶段 B(彻底)**:自研最小自动化通道,只暴露导航 / 点击 / 输入 / 取文本 / 快照,
  **不实现调试协议** → 从根上没有泄漏面。

这条路的战略含义:CloakBrowser **永远做不到**,因为「Playwright 零迁移」这个卖点
把它焊死在 CDP 上了。

### 支柱 2 · Persona 引擎(不是随机,是自洽)

```
seed → 完整画像 → 交叉校验 → 持久化 → 缓慢演化
```

- 一个 seed 生成整套互相对得上的值:UA + 平台 + 屏幕 + 缩放 + GPU + 字体子集 +
  时区 + 语言 + WebGL + Audio + ClientRects
- **启动前校验**:任意两项矛盾即拒绝启动(不让网站替我们发现)
- **启动后回归**:跑 creepjs / browserleaks,分数低于阈值即报警
- **持久化**:同一 persona 跨会话保持 cookie、localStorage、访问历史
- **演化**:字体慢慢装、历史慢慢长,而不是每天换一个陌生人

### 支柱 3 · 可信(可复现构建)

- 源码全开,**Apache-2.0(候选,待拍板)**(带专利授权,比 MIT 更适合被企业采用)
- **可复现构建**:任何人都能编出逐字节相同的二进制
- **零遥测**:默认断网可跑;网络请求可完整抓包审计
- **不限并发**:直接对标 CloakBrowser 的 1 并发限制

## 三、技术架构(v1 草案)

```
┌─────────────────────────────────────────────┐
│ 编排层    persona 池 · 任务调度 · 代理绑定      │  ← Python / TS SDK
├─────────────────────────────────────────────┤
│ 运行时    Persona 引擎 · 一致性校验 · 行为层     │
├─────────────────────────────────────────────┤
│ 通道层    CDP 双端补丁 → 自研协议(阶段 B)      │  ← 本行已作废(见下注)
├─────────────────────────────────────────────┤
│ 内核层    Chromium fork(ungoogled 基底)       │
└─────────────────────────────────────────────┘
```

> ⚠️ **通道层定性已作废**:本图写「自研协议(阶段 B)」为必然且称其为护城河。
> REA 结论(`附录B-REA逆向结论.md` B1/B2)把靶心收窄为「是否必须不发 `Runtime.enable`」,
> 阶段 B 因此降为**条件性工作**,判据归 M0。以 `方案-v3-终稿.md` §四 A2 为准。

**为什么用 Chromium 而不是 Firefox**:市场份额决定检测方的优化目标。Firefox 指纹太特殊,
反而显眼;Chromium 是「大众脸」。

**为什么基于 ungoogled-chromium**:已去掉 Google 服务与遥测,是干净底座。
`adryfish/fingerprint-chromium` 证明此路可通,其补丁开源(延迟一个月发布),可参考甚至直接合入。

**v1 的已知张力**(留待 v2 解决):CloakBrowser 的哲学是「一次性伪装身份」,
而 ego lite 的哲学是「真实登录身份 + 人机共用」。两者方向相反,
合并方案必须显式给出「多身份档案管理器」模型来消解这个矛盾。

## 四、里程碑

> ⚠️ **本表已作废。** 里程碑编号与工期以 `方案-v3-终稿.md` 第六节为唯一准。
> 本表写于「还没决定 fork ego 的 MIT harness」之前,因此 M2 位置与工期(4–6 个月到 M3)都偏保守。

| 阶段 | 目标 | 产出 | 验收 | 工期 |
|---|---|---|---|---|
| **M0 取证** | 先证明「CDP 是最大漏洞」,而非凭感觉 | 检测基准台 + 报告 | 同机同代理下,CloakBrowser vs 裸 Playwright vs 打补丁版,在 ≥8 个检测站的分数表 | 1 周 |
| **M1 底座** | 跑通 Chromium 构建流水线 | 可运行 fork 二进制 | 本机可启动;**rebase 一条命令完成** | 3–4 周 |
| **M2 通道** | 消灭 CDP 泄漏 | 双端补丁版 | `Runtime.enable` 检测项归零 | 4–6 周 |
| **M3 Persona** | 自洽画像 + 持久身份 | SDK + 校验器 | 100 个 seed 无一矛盾;重启后身份保持 | 3–4 周 |
| **M4 行为** | 内容驱动节奏 | 行为引擎 | 停留时间与内容长度相关性 > 0.8 | 4 周 |
| **M5 分发** | 签名发布 + 自动更新 | 安装包 + CI | 第三方能复现构建 | 2 周 |

**诚实工期(已作废,见上表说明)**:一人全职到 M3 约 4–6 个月。真正的长期成本不在开发,
而在**每 4 周跟一个 Chromium 版本** —— 所以 M1 的第一优先级不是功能,
是把 rebase 流水线做成一条命令。

## 五、变现设计

核心原则:**浏览器本体永久免费、开源、不限并发。** 这是打 CloakBrowser 最有效的武器,
也是信任的基础。只收「运维复杂度」:

| 层级 | 内容 | 定价思路 |
|---|---|---|
| **免费** | 完整浏览器 + persona 引擎 + 无限并发 | 永远免费 |
| **Pro 云** | persona 云同步(跨设备同一身份)、托管代理池、会话录制回放 | $20–50/月 |
| **团队** | 多人共享 persona 库、权限、审计日志 | $200+/月 |
| **企业** | 私有构建(定制补丁)、SLA、合规报告、部署支持 | 年费 |
| **不卖的** | 并发数、基础指纹能力、更新 | 卖这些就是重蹈 CloakBrowser 的覆辙 |

附加一条:**检测基准订阅**。定期发布「当前主流检测站通过率基准」,
既是营销,也是行业话语权。

## 六、风险清单

| 风险 | 说明 | 对策 |
|---|---|---|
| **法律** | 双用途工具,用于欺诈/撞库会反噬项目 | 明确 AUP:禁止未授权访问金融/医疗/政务认证系统;不提供「自动过验证码」 |
| **维护** | Chromium 每 4 周一个版本,补丁持续失效 | rebase 流水线 + 自动化回归是 M1 硬要求 |
| **军备竞赛** | 没有永久胜利 | 定位为「持续维护的基准」,不是「一劳永逸」 |
| **信任** | 一旦被发现偷偷上报,项目立刻死 | 可复现构建 + 零遥测 + 全量抓包审计 |
| **封号归因错误** | 用户会把所有封号归咎于工具 | 文档必须写清:平台封号是多因素决策(IP 段、支付、行为、账号年龄),指纹只是其中一环 |
