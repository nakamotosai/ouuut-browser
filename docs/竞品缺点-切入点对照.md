## 一、CloakBrowser 的缺点 → 对冲动作

| # | 缺点 | 证据 | 我们的动作 |
|---|---|---|---|
| C1 | **走 CDP** | 【第三方】Playwright → CDP;`Runtime.enable` 泄漏被 Cloudflare/DataDome 使用(rebrowser 公开研究) | 阶段 A 双端补丁先按住 `Runtime.enable`;阶段 B(自研进程内通道)**为条件性工作,判据归 M0** —— REA 显示「不发该命令」可能已足够(`附录B` B2),若够则不做 |
| C2 | **无一致性引擎** | 【实测】改时区/语言后屏幕分辨率不跟随;参数全靠调用方手传 | seed → 整套自洽画像;启动前交叉校验,矛盾即拒绝启动 |
| C3 | **无身份持久化** | 【实测】无 persona 概念,每次都是全新陌生人 | 档案持久化(cookie/历史/字体演化),同一 seed 跨会话同一身份 |
| C4 | **行为层是死算法** | 【官方】`humanize=True` 是固定曲线,不读内容 | 内容驱动:停留时间与内容长度相关;打字含错字-退格-重打 |
| C5 | **二进制闭源** | 【官方】`BINARY-LICENSE.md` 明写 proprietary,禁派生禁逆向 | 源码全开 + 可复现构建 + 零遥测 + 抓包可验 |
| C6 | **限并发 + 许可限制** | 免费档 1 并发 =【实测/官方】(`License: Free (no key)`,条款写明 1 concurrent session);「最新 major 需登录」「条款禁止绕过会话限制」=【官方】条款级。**注:本机实测 4 进程并发未被本地拦截** → 限制是**条款级 + 服务端计数**,不是本地硬闸 | 不限并发、无许可服务器、最新版永久免费(并且我们不做服务端计数) |
| C7 | **无公开可复现基准** | 【官方】「通过 50+ 检测站」无可复现分数表 | 公开检测基准并定期发布(既是产品,也是营销) |
| C8 | **失败静默降级** | 【实测】缺 `socksio` 时 WebRTC 出口 IP 解析失败,仅打印告警后继续跑 | 关键隐身项失败 = 拒绝启动,不静默降级 |
| C9 | **免费档二进制严重过期:「版本陈旧」本身就是信号** | 【实测】本机免费档二进制 `chromium-146.0.7680.177.5`,UA 报 `Chrome/146.0.0.0`;而 **2026-10-24 真实 Chrome stable = 157.0.8103.15**(chromiumdash 官方接口)—— **落后 11 个大版本**。Pro 档才给 154/155。【推断】真实 Chrome 自动更新,长期停留在 11 版之前的用户极罕见,版本新鲜度本身就是可用的判别特征 | **F2(一条命令 rebase)从「维护卫生」升级为「反检测能力」**:跟 stable 约 4 周一版,永远不发陈旧版本号;绝不靠改 UA 假装新版本(特性检测会对不上) |
| C10 | **启动参数没清干净:竟带着 `--disable-ipc-flooding-protection`** | 【实测】M0 第 2 轮 `bot-detector.rebrowser.net`:同一轮同出口下 **CloakBrowser 唯一红项就是 `ipcFloodingProtection`**(`applied: 300`,即 `history.replaceState()` 300 次全过;正常 Chrome 200 次后限速)。对照:`pw-hardened` / `patchright` 均已 🟢。证据 `probe/out/20261024-020503/matrix.json` | 启动参数白名单化:每一个 flag 都要能说明「真实 Chrome 也这样」;`--disable-ipc-flooding-protection` / `--disable-popup-blocking` / `--enable-unsafe-swiftshader` 一律不带 |
| C11 | **仍有 2 项黄:`viewport` 与 `popupBlocking`** | 【实测】同上一轮:CloakBrowser 在 `viewport`(Playwright 默认 1280×720)与 `popupBlocking`(无点击即弹窗)上仍为 🟡。而 `pw-hardened` 这两项都已 🟢 —— 说明**商业方案也有没做完的角落** | 视口按真实屏幕;不带 `--disable-popup-blocking`。这两项**零成本**就能超过竞品 |

## 二、ego lite 的缺点 → 对冲动作

### 2.1 结构性空白(最值钱的三条)

| # | 缺点 | 证据 | 我们的动作 |
|---|---|---|---|
| **E8** | **仅本机、仅 loopback,远程能力被主动砍掉** | 【二进制】`run-*.mjs`:`Refusing to bind Ego to non-loopback host ... remote access has been removed`;`EGO_AUTH_TOKEN`/`EGO_PUBLIC_URL`/`EGO_ALLOW_INSECURE_REMOTE` 现在是**启动错误**「Ego only accepts loopback connections」;默认服务端口 3773 仅 127.0.0.1 | **服务器 / 多机编排一等公民** —— 它把自己锁死在桌面 |
| **E9** | **未暴露无头入口** | 【二进制】CLI/SDK 无 headless flag,daemon 从不传 `--headless`;二进制内有 stock Chromium 无头代码,但**「裸启动能否跑通」未实测**(取证报告明确标 UNVERIFIED) | 无头与桌面同等优先级 |
| **E4** | **遥测与「无数据收集」宣传矛盾** | 【二进制】`https://eventflow.citrolabs.ai/metrics`(UMA 上传,带头 `X-Ego-Device-Id` / `X-Ego-User-Id`);Sentry 崩溃上传(**运行中进程的命令行里就能看到**,这条是【实测】);`EGO_LANGFUSE_*` → `us.cloud.langfuse.com`;`update_telemetry.json` 含 `device_region_country`/`device_timezone`/uuid;Variations 种子服务器由 Google 改指 Citro。**注:未抓包,运行时是否真的连出去标 UNVERIFIED**(政策文本自认默认开启崩溃上报与用量分析 → R3,那条是【官方】) | **零遥测**写进产品定义,并用可复现构建让它可被第三方验证 |

### 2.2 其余缺点

| # | 缺点 | 证据 | 我们的动作 |
|---|---|---|---|
| E1 | **零指纹能力** | 【二进制】`help()` 全集无任何 UA/平台/canvas/时区/GL 覆盖入口;`fingerprint`/`spoof` 命中全是 Chromium/ICU/XNN 自带符号;`navigator.webdriver` 是**原生 getter** 返回 false(因为没传 `--enable-automation`,不是补丁) | C++ 层指纹补丁 |
| E2 | **档案不隔离** | 【官方】本机带文件复述:文档自述「该 profile 的 cookie jar 与 HTTP 缓存与你自己的标签页、以及其他所有任务空间共享」,**引其自测数字:该 profile 持有 1161 个域名的 3478 个 cookie**(数字出自厂商自带文档,非我方测量;**我方实测的是另一端**:`Network.getCookies` 在该页只返回 0 条);全机只有一个 profile =【二进制】;独立第三方的 cookie 跨 Space 实验见 R4 #319、R5 | 硬隔离 + 把「cookie 跨档案读写必须失败」写成验收反例(对应 ego 的 #319 现象) |
| E3 | **特权上下文可直接偷 cookie** | 【官方】issue #315(链接与原文见 R4):模型生成的 JS 跑在特权 Node 上下文,能调原始 CDP + 任意出网 → 可读 HttpOnly cookie 外发;文档自述 `Network.clearBrowserCookies` 会清空**整个 profile**(含用户自己的登录态) | 权限边界:档案脚本不得出网、不得调原始调试协议 |
| E5 | **本体闭源** | 【官方】`AGENTS.md` 自述仓库只有 harness,浏览器本体另发(R1);二进制签名 `CITRO LABS PTE. LIMITED`(Certum,签名有效)=【二进制】 | 全开 |
| E6 | **快照体积宣传失真** | 【第三方】独立实测 HN 页 7,823 tokens(视口)/ 11,867(整页),官方称「200–400」;对比 agent-browser 4,742 —— 比它更大。原始来源与日期见 R5 | 快照体积作为可量化验收指标 |
| E7 | **Windows 是 beta 且真实坏掉** | 【官方】#544 更新后外链静默丢失、#546 Chrome 156 档案导入失败、#547 UAC 关闭时 exit 10(链接见 R4) | Windows 一等公民 |
| E10 | **承诺未兑现** | 【官方】README 的 `Reusable skills` 长期 `coming soon`(R6) | 少承诺,未实现的不写进 README |
| E11 | **多档案只靠导入** | 【二进制】`import --browser chrome\|edge\|brave` —— 只能把别的浏览器的档案搬进来,自己不产身份 | 原生多档案(三种 kind) |

### 2.3 一条反直觉的发现(值得单独记)

ego lite 的 `navigator.webdriver === false` **不是隐身能力**,而是「它没打开自动化开关」的自然结果 ——
它把 `--enable-automation` 留在 stock 字符串里没启用。

**推论【推断】:很多被当作「隐身」的东西,其实只是「没触发显式标记」。真正的检测面在协议层与一致性层。**
这印证了把重点放在 CDP 与一致性上是对的,而不是继续堆 JS 层面的伪装。

## 三、两家共同的缺点(最强切入点)

| # | 共同缺口 | Cloak | ego | 我们的动作 |
|---|---|---|---|---|
| **G1** | **同一浏览器里没有「多身份」** | 只有一次性假身份 | 只有真实的你自己(单 profile) | **档案一等公民**:`real` / `persona` / `disposable` |
| G2 | 都不做内容驱动的行为 | 固定曲线 | 无行为层 | 内容驱动行为引擎 |
| G3 | 都不可审计 | 闭源二进制 | 闭源本体 + 遥测 | 可复现构建 + 零遥测 |
| G4 | 都没有公开可复现的检测基准 | 营销话术 | 无此能力 | 公开基准 + 定期发布 |
| G5 | 隔离都不硬 | 无档案概念(结构上不可能) | cookie 跨 Space 共享(官方承认) | 硬隔离 + 反例验收 |
| G6 | 都锁在桌面或无头的一端 | 无头可跑但无身份管理 | 只有桌面,远程被砍 | 桌面与服务器同一套 API |

**G1 与 G6 是核心。** 两家分别解决了「隐身」和「人机共用」的一半,
谁都没把它们放进同一个抽象,也谁都没打通「桌面 ↔ 服务器」这条线。

**注**:上表是**工作假设**,不是市场普查结论。M0 的任务之一就是证伪它
(需补一份第三方反检测浏览器的横评,现有证据只覆盖被本机检查过的两家)。
