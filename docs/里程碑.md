  - **硬隔离 = 两层防线,而且隔离是结构性的**(不靠"记得加检查"):
    - **第一层 句柄**:`archive.cookiesFor(profileId, send)` 交出绑死该档案的句柄,
      `browserContextId` 由句柄**覆盖式注入** —— 调用方**没有参数**能省略/覆盖/改写它。
      **正确用法即默认用法**;#319 的成因恰是"省略了 browserContextId → 落到默认档案"。
      句柄冻结,连属性都改不动
    - **第二层 发送侧闸** `checkCookieCommand()`:没带 `browserContextId` → 拦;指向别的档案 → 拦;
      指向本档案 → 放行;非 cookie 方法 → 放行(不误伤)。
      与 user-control 门同理:只有我们这层知道"该用哪个档案"
  - **假浏览器真的按档案分池存 cookie**,且**不给参数就落到 `default` 池**(Chrome 的真实行为)。
    另有一条**地基测试**专门断言"绕过引擎的朴素写法**真的会泄漏**" ——
    若连朴素写法都不泄漏,后面那堆"拦住了"就没有意义
  - **变异测试(证明断言承重,不是装饰)**:
    | 变异 | 结果 |
    |---|---|
    | 闸无条件放行(等于忘了做隔离) | **4 个用例红**,含「#319 原样重现」 |

    | GPU 从两个平台混着挑 | **「100 个 seed 零矛盾」红** |
  - **13 条规则逐条可证伪**:每条规则各注入一次矛盾,断言**正是那条**报警;
    另有「合法画像必须判 ok」挡住"逢事必报"
  - **生成器与校验器是两个独立实现**:生成器从**一张自洽底座表**选一组(OS+地区+GPU+分辨率)
    再派生其余项 → 矛盾在**构造上不可能产生**;校验器**不读生成器的意图**,只看画像本身。
    若二者是同一个函数的两半,那条"100 seed 零矛盾"就毫无信息量
  - **`real` 的不可变性**:不许创建、不许销毁(硬错误,不是警告);恰好一个,且恒为
    `isDefault`(由 kind 推导,不接受调用方传)

## M6 · 行为

- **目标**:内容驱动节奏
- **验收**:停留时间与内容长度相关性 > 0.8
- **状态**:**✅ 验收达成**(`native/binding/pacing.mjs` + 16 条用例)
- **模型**:`停留 = 思考时间 + 阅读时间`
  - 阅读时间 = 内容长度 / 阅读速度,**速度每次重取**(11~19 字符/秒)
  - 思考时间 = 对数正态(400~1400 ms,右偏 —— 真人会先看一眼再决定读不读)
  - 三种阅读模式:扫读 10% / 正常 75% / 细读 15%
- **实测相关性**:8 个 seed 全部落在 **0.91~0.96**
  - 分布:200 个页面(200~20000 字符,对数均匀)
  - 被上限夹住的样本剔除后再算(夹住之后不再随长度变化)
- **⚠️ 只验「> 0.8」是不够的**:一个 `y = ax + b` 能轻松过 0.99,
  那等于**把公式交给观察者** —— 采几个页面就能反推。所以同时守**上界** `r < 0.98`,
  并要求分布是**多峰**的
- **一处值得记的教训**:先写成"每次重取阅读速度",结果 r=0.98(太直);
  加上三种模式后降到 0.93。但**只靠模式**就能撑住相关性,于是把速度改成常数
  **不会**让相关性掉下来 —— 而固定 15 字符/秒本身是可被指纹化的常数。
  为此专门补了一条断言:**同一模式内「停留/长度」比值的变异系数 > 0.08**,
  这条才真正钉住速度波动
- **边界**:下限 800 ms(0 毫秒停留是最明显的机器特征)· 上限 20 分钟且**明说被夹住**
  (`capped: true`),否则统计时没法剔除、会把相关性算低
- **变异测试**:只剩一种模式 → 2 红;不钳制 → 4 红;速度取常数 → 1 红(补断言后)
