    `bot-detector.rebrowser.net` → **11 通过 / 3 红 / 2 黄**(16 项计分)
    - **关键两份绿**:`headless` 🟢("No signs of headless Chrome")、`workerConsistency` 🟢
      —— 这正是补丁 0001 的目标,而且**连 Web Worker 的 UA 一起修好了**
    - 另外 `storagePartitioning` / `ipcFloodingProtection` / `popupBlocking` / `viewport` /
      `cdpBindingGlobals` / `documentInterception` / `mobileEmulation` / `pwInitScripts` / `bypassCsp` 均 🟢
    - **3 条红已查明是「测试驱动」的产物,不是内核问题**(见下)
- **3 条红的归因(有对照证据,不是猜)**:
  我们这次是用 **omp 的 CDP harness** 驱动的,而 harness 会覆盖 UA 与发 CDP 命令:
  | 红项 | 站点的原文说明 | 归因 |
  |---|---|---|
  | `platformMismatch` | *"That happens when the user agent is overridden without userAgentMetadata, e.g. Puppeteer page.setUserAgent(string)"* | **驱动覆盖了 UA** |
  | `runtimeEnableLeak` | CDP `Runtime.enable` | **驱动发的**(不是浏览器自发) |
  | `navigatorWebdriver` | `Object.getOwnPropertyNames(navigator) = ["modelContext"]` | `navigator.modelContext` 被放在**实例**而非原型上(Chromium 特性位置问题,与补丁无关) |
  | `useragent` 🟡 | "Cannot detect Chrome version"(`useragentVersionItems: []`) | 空 brands 的连带 |
  | `nativeTampering` 🟡 | 同 `navigator.modelContext` | 同上 |
  **对照实验**:用**原生 Chromium(154)**在**同一套 harness**下跑同一站 → 同样得到
  `brands: []` / `platform: ""` —— **证明这几条红是 harness 造成的**。
- **❌ M1 尚未完全验收**(不掩饰):
  - **`rebase` 一条命令实测没做**:这次是**手工一步步**跑通的(gn gen / autoninja 直接调),
