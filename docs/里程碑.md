- **证据**:
  - **硬隔离 = 两层防线,而且隔离是结构性的**(不靠"记得加检查"):
    - **第一层 句柄**:`archive.cookiesFor(profileId, send)` 交出绑死该档案的句柄,
      `browserContextId` 由句柄**覆盖式注入** —— 调用方**没有参数**能省略/覆盖/改写它。
      **正确用法即默认用法**;#319 的成因恰是"省略了 browserContextId → 落到默认档案"。
      句柄冻结,连属性都改不动
    - **第二层 发送侧闸** `checkCookieCommand()`:没带 `browserContextId` → 拦;指向别的档案 → 拦;
      指向本档案 → 放行;非 cookie 方法 → 放行(不误伤)。
      与 user-control 门同理:只有我们这层知道"该用哪个档案"
  - **假浏览器真的按档案分池存 cookie**,且**不给参数就落到 `default` 池**(Chrome 的真实行为)。
    另有一条**地基测试**专门断言"绕过引擎的朴素写法**真的会泄漏**" ——
    若连朴素写法都不泄漏,后面那堆"拦住了"就没有意义
  - **变异测试(证明断言承重,不是装饰)**:
    | 变异 | 结果 |
    |---|---|
    | 闸无条件放行(等于忘了做隔离) | **4 个用例红**,含「#319 原样重现」 |
    | 句柄改成 `{browserContextId: bound, ...params}`(调用方可覆盖) | **2 个用例红** |
    | 时区改成独立随机(破坏底座表自洽) | **「100 个 seed 零矛盾」红** |
    | GPU 从两个平台混着挑 | **「100 个 seed 零矛盾」红** |
  - **13 条规则逐条可证伪**:每条规则各注入一次矛盾,断言**正是那条**报警;
    另有「合法画像必须判 ok」挡住"逢事必报"
  - **生成器与校验器是两个独立实现**:生成器从**一张自洽底座表**选一组(OS+地区+GPU+分辨率)
    再派生其余项 → 矛盾在**构造上不可能产生**;校验器**不读生成器的意图**,只看画像本身。
    若二者是同一个函数的两半,那条"100 seed 零矛盾"就毫无信息量
  - **`real` 的不可变性**:不许创建、不许销毁(硬错误,不是警告);恰好一个,且恒为
    `isDefault`(由 kind 推导,不接受调用方传)
  - 全仓累计 **98 个用例**(M2 47 + M3 51),`node --test native/binding/*.test.mjs native/bin/*.test.mjs`
- **⚠️ 一次无结论的变异(值得记)**:第一次变异尝试把源文件写成了语法错误,
  于是"整个文件加载失败"而不是"逻辑被拆掉后测试没抓住"。**变异的失败模式也要检查**,
  否则会把"文件坏了"误当成"测试抓住了"

- **证据**:
  - **每条规则都有出处,不是照抄某个库的黑名单**(ADR-012 明令:**不要直接用 patchright**,

    | `Page.addScriptToEvaluateOnNewDocument` / `setBypassCSP` / `setDocumentContent` | 页面注入 | 检测项 `pwInitScripts` / `documentInterception` / `bypassCsp` |
    | `Emulation.setDeviceMetricsOverride` 等 | 设备/自动化模拟 | 检测项 `mobileEmulation` |
  - **`Emulation.setUserAgentOverride` 是「改写」不是「拦」** —— 因为检测站红的不是"覆盖了 UA",
    而是"覆盖了 UA 却**没给** `userAgentMetadata`"(brands 变 `[]`)。这条直接来自 **M1 的对照实验**。
    **改写不成功则 fail-closed**:补不齐 metadata 就**绝不发**(报 `OUUUT_UA_METADATA_REQUIRED`),

  - **放行也是有据的**:`Target.setAutoAttach` / `Page.enable` / `Network.enable` /
