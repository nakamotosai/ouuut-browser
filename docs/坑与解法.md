## 坑-1 · `bash` 指向 WSL 启动器

- **现象**:`i/o error: stream did not contain valid UTF-8`
- **根因**:系统 PATH 里的 `bash` 解析到 WSL 的启动器,不是 Git Bash
- **正解**:显式调用 `"C:/Program Files/Git/bin/bash.exe"`
- **备注**:2026-10-24 复核,本项目内的 `bash` 工具调用走的是 Git Bash(`uname` 报 `Windows_NT ... MS/Windows`),未复现此坑;脚本仍建议显式写全路径以求稳

## 坑-5 · `secrets_manager.py read` 的两个陷阱

- **陷阱 1:两个命令返回结构不同**
  - `read <service>` → `{"service", "num_keys", "keys": {...}}`
  - `read <service> <key>` → `{"service", "key", "value"}`
- **陷阱 2:`read <service>` 里的 value 是【打码】的**
  - 整服务读出的值形如 `http...7081` / `b602...1a53`(定长 11 字符),**不是真值**
  - 照着它去请求 → `ValueError: unknown url type: 'http...7081/api/v1/user'`
- **正解**:要真值一律 `read <service> <key>` 然后取 `['value']`;
  整服务读只用来**列 key 名**

## 坑-6 · 别用 `gh auth login --with-token` 喂空 stdin

- **现象**:命令被挂起(本会话里被后台化为 `bg_N`)
- **根因**:token 文件为空(上一步提取失败)时,`gh` 转为交互式等待
- **正解**:先校验 `wc -c` 非 0 再喂;或干脆用 `GH_TOKEN` 环境变量

## 坑-7 · `curl` 下载大文件不要走 bash 工具

- **现象**:工具提示改用 context-mode MCP,拒收
- **根因**:可能把原始 HTTP 灌进上下文
- **正解**:用 `eval` + Python `urllib.request.urlopen(...).read()` 直接写盘(本项目 LICENSE 即此法)

## 坑-8 · Chromium 源码树的许可结论不要只信单一渠道

- **现象**:`ungoogled-chromium` 的 `LICENSE` 文件只声明其**补丁集**为 BSD-3-Clause,
  不含 Chromium 本身的许可
- **根因**:它是**补丁集 + 构建工具**,不是完整发行版
- **正解**:Chromium 本身的许可以 `chromium.googlesource.com/chromium/src/+/main/LICENSE`
  与分发时 `about:credits` 为准。两者在 `NOTICE` 分别登记

## 坑-9 · Gitea 建仓:API 走不通,但「推送即建仓」可用

- **现象**:
  - `POST /api/v1/user/repos` → `403 required=[write:user]`
  - `POST /api/v1/admin/users/sai/repos` → `403 required=[write:admin]`
  - 且经 Tailscale(`198.51.100.7:7081`)的 **POST** 偶发 `ConnectionResetError(10054)`,
    而 **GET 正常**(`/api/v1/user` 200、`/api/v1/version` 200)
- **根因**:现有 `gitea/api_token` 的 scope 是
  `write:organization,write:issue,write:repository,read:user` ——
  Gitea 1.27.3 的**建仓端点**不在 `write:repository` 覆盖范围内
- **正解**:**直接 `git push` 到尚不存在的仓库** —— 该实例启用了 push-to-create,
  推送即建仓。验证:`GET /api/v1/repos/sai/ouuut-browser` → 200,`private: true`
- **附带**:Gitea SSH 走 `ssh://git@vps-jp-gitea/sai/<repo>.git`(别名端口 2222,密钥
  `home-windows-id-ed25519`)
