# 原生层接口(JS harness ↔ 内核的接缝)

> **本文件是我们自己的规格,不是上游文档的抄录。** 事实来源是 vendored 副本里的
> `harness/docs/native-bindings-api.md`(那 24 KB 是上游 JS harness 与其**闭源原生层**
> 之间的接缝规格)。本文件把它**提炼成我们要实现的东西**,并标出我们与上游的差异。
>
> 为什么现在写:`tools/20-rebase.sh` 里那批内核补丁要打什么,取决于**这层接口要暴露什么**。
> 规格先定,补丁才不会返工。见 `docs/方案-v3-终稿.md` §五。

---

## 一、运行时模型

```
┌──────────────────────────────┐
│ 我们的 CLI 入口              │  ← 对应上游 `ego-browser nodejs < script`
│  注入 globalThis.<ns>        │
├──────────────────────────────┤
│ JS harness(vendored,会改)   │  ← harness/ —— TaskSpace / 快照 / 选择器 / site-learnings
│  只依赖下面这组方法          │
├──────────────────────────────┤
│ 原生层(**我们自写**)        │  ← 通道 / 快照生成 / 档案 / 指纹
└──────────────────────────────┘
```

| 要点 | 上游的做法 | 我们的决定 |
|---|---|---|
| 命名空间 | `globalThis.ego` | **`globalThis.ouuut`**(避免与安装了 ego lite 的机器冲突) |
| 调用形态 | 每个方法返回 `Promise`,结果经浏览器侧 `NodeClient` 转 `base::Value` | 同 |
| 任务上下文 | 脚本内 `ego.useTaskSpace(id)` 选定;**只影响本次 Node 调用** | 同(这是好设计) |
| 档案选择 | **在建 task space 时**选,不在 `useTaskSpace` 里 | 同 |
| 参数错误 | 抛 `TypeError`,`error_code = EGO_INVALID_ARGUMENT` | 同(代号改 `OUUUT_*`) |
| 其它失败 | **两种形态**:普通命令 resolve 一个 `{error, error_code}` 对象;`snapshot()` **reject** 一个带 `error_code` 的 `Error` | ⚠️ **我们改成统一**:一律 reject 带 `error_code` 的 `Error`。混两种形态会让调用方写双份分支 |

## 三、错误码(15 个,我们要定义自己的对应集)

上游的:`EGO_BROWSER_UNAVAILABLE` · `EGO_CDP_CHANNEL_UNAVAILABLE` · `EGO_CDP_SEND_FAILED` ·
`EGO_INVALID_ARGUMENT` · `EGO_INVALID_RESULT_PAYLOAD` · `EGO_OPERATION_FAILED` ·
`EGO_PROFILE_NOT_FOUND` · `EGO_RESULT_CONVERSION_FAILED` · `EGO_SNAPSHOT_FAILED` ·
`EGO_TASK_HOST_DISCONNECTED` · `EGO_TASK_SPACE_INACTIVE` · `EGO_TASK_SPACE_NOT_FOUND` ·
`EGO_TASK_SPACE_NOT_SELECTED` · `EGO_TASK_SPACE_UNAVAILABLE` · `EGO_TASK_SPACE_USER_IN_CONTROL`

**我们要加的**(上游没有,因为上游没有这些概念):

| 新码 | 场景 |
|---|---|
| `OUUUT_PROFILE_ISOLATION_VIOLATION` | 跨档案读写被拦下(M3 的硬隔离验收) |
| `OUUUT_CONSISTENCY_CHECK_FAILED` | 指纹一致性校验不通过 → **拒绝启动**(F5) |
| `OUUUT_EGRESS_MISMATCH` | 出口 IP 地理与画像矛盾(F6) |
| `OUUUT_WEBRTC_LEAK_DETECTED` | 出口一致性自检发现 WebRTC 泄漏(ADR-014) |
| `OUUUT_INVISIBLE_ITEM_FAILED` | 关键隐身项失败 → **拒绝启动,不静默降级**(竞品缺点 C8) |

## 四、快照契约(上游提了要求,我们必须照做或明确改进)

来源:`harness/docs/native-snapshot-ref-requirement.md`。

### 4.1 文本化简(内核侧做,不是 JS 侧过滤)

- 丢掉空 / 纯空白(含 NBSP)/ 只含零宽格式字符的文本节点
- 丢掉「没有名字且没有子节点」的 `container`
- 「没有名字的 container 只剩一个子节点」→ 用那个子节点**替换**它
- **保留**:有名字的、带 ref 的 container;`image` / `svg_root` / `canvas` / `iframe` /
  `root` / list item / table cell
- 化简**不得**改变剩余节点的顺序、ref、stable locator、URL、iframe 边界
- **绝不**因为「不可交互」或「父容器被化简」而删掉非空的页面文本
- **验收**:同一 fixture 连拍两次,第二次输出**逐字节相同**;兄弟分组仍可区分;每个 ref 仍解析到原节点

> **为什么这是内核的活**:在 JS 侧过滤完整快照**不会减少内核工作量,也不会减少传输量**。

### 4.2 iframe 里的可操作节点必须有 ref

`refs` 里要给**跨 renderer**唯一的 `refId`,并带 `frameId`:

```js
{ refId: 901, backendNodeId: 21, frameId: "FRAME_OR_OOPIF_TARGET_ID",
  role: "button", name: "Run iframe action" }
```

- 同一份快照里 `refId` **跨进程唯一**(这是给 agent 看的编号)
- `backendNodeId` 只在它的 renderer 内唯一
- 拍快照**不得**激活 / focus / reload 任何 frame

### 4.3 快照的**实测格式**(2026-10-24,在 ego lite 上跑出来的)

`native/smoke/taskspace-smoke.mjs` 在 ego 上跑通后拿到的真实输出 —— **这是我们自写原生层要对齐的格式**:

```
[p2 "Example Domain" | space "ouuut-m2-smoke"(43): 2 managed, 0 untracked — p1 "新标签页", p2* "Example Domain"]
root
  svg_root
  paragraph
    text "该域名仅用于文档示例,无需获得许可。..."
  paragraph
    text "This domain is for use in documentation examples ..."
```

可归纳出的要点:

| 观测 | 含义 |
|---|---|
| `snapshot()` 返回**字符串**(不是对象) | 与上游文档说的「序列化 `content`」一致 |
| 第一行是**任务空间/页面头**:`[<label> "<title>" \| space "<name>"(<id>): N managed, M untracked — <各页 label 与标题>, <当前页带 *>]` | agent 一眼看到「我在哪个空间、开了哪些页」 |
| 之后是**两空格缩进的树**,节点是**角色名**(`root` / `svg_root` / `paragraph` / …) | 与 a11y 角色同构 |
| 叶子形如 `text "<页面原文>"` | **页面文本原样保留**(与上游「绝不删非空页面文本」的要求一致) |
| 长度 1175 字符(example.com) | 作为量化基线:同一页面我们的实现应量级相当 |

**验收提示**:M2 接通后,同一脚本在同一 URL 上应产出**结构同形**的快照(节点名与缩进语义一致);
长度不必逐字节相同,但**不应少掉页面文本**。

### 4.4 stable locator 必须唯一且指向同一个节点

- 匹配 0 个、匹配多个、或唯一匹配到**不同** `backendNodeId` → **都算无效**
- 必须覆盖:同名按钮重复、同名但一隐一显、顶层与 iframe 里同名、元素类型不匹配
- 建立不了唯一性和同一性时**省略 locator**;`content` 里**不许**出现
  `loc=unstable` / `loc=ambiguous` 这类状态串

## 五、SDK 生命周期与对话框

来源:`native-sdk-lifecycle-requirement.md`、`native-javascript-dialog-requirement.md`。

| 要求 | 内容 |
|---|---|
| **卸载** | 卸载/替换内嵌 JS 上下文前,宿主必须 **`await disposeEgoSdk()`**。它会 reject 未完成的 CDP 请求、清 Page/session 状态、只有在回调仍归该实例所有时才摘掉 `onCDPMessage` / `onSendCDPMessageError` |
| **语法诊断** | heredoc 编译失败时,必须报出**消息 + 一行一列的 line/column + 对应源码行**(不能只给一个 `node:internal/vm` 栈) |
| **JS 对话框** | 页面 `alert` / `confirm` / `prompt` 归 agent 控制;**`beforeunload` 上游仍未解决** |

> **`beforeunload` 是一条已知空白** —— 我们若要做,得自己定契约(见 §七)。

## 六、我们与上游的差异(有意为之)

| 维度 | 上游 | 我们 |
|---|---|---|
| 档案种类 | 无概念,机器上只有一个 profile | **三种 kind**:`real` / `persona` / `disposable`(ADR-007) |
| 档案隔离 | ❌ 共用一个 cookie 池(竞品缺点 E2) | **硬隔离**,跨档案读写必须失败(M3 验收) |
| 指纹 | ❌ 二进制级确认没有(M0 实测:它在 bot-detector 上 16/16 全绿靠的是**品牌 + 无头标识**补丁,不是完整指纹引擎) | 一致性引擎:seed → 自洽画像;启动前校验,矛盾即拒绝启动(F5) |
| 出口一致性 | ❌ | 启动时校验出口 IP 地理 vs 画像(F6)+ WebRTC 抑制(ADR-014) |
| 无头 / 服务器 | ❌ 主动砍掉远程能力,锁死 loopback | 一等公民(M5,ADR-008) |
| 遥测 | ❌ UMA + Sentry + Langfuse(竞品缺点 E4) | 零遥测,断网全功能可跑(F9) |
