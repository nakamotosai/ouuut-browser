# ouuut 浏览器 · 功能范围(做 / 不做)

> 日期:2026-10-24 · 定位:**范围唯一正本**。任何功能提案先查本文件;
> 不在「做」表里的,默认不做;想加要先改本文件并说明理由。
> 每条「做」都挂里程碑与可复现验收;每条「不做」都写明理由,避免半年后有人重新提议。

---

## 〇、一句话范围

**做一个「可审计、多身份、能上服务器的隐身浏览器内核 + 代码优先的 agent 运行时」。
不做产品化外壳(GUI 管理器、账号体系、托管云服务),不做灰产形状的功能。**

---

## 一、会实现的功能

### 1.1 核心层(M1–M3,决定项目成立与否)

| # | 功能 | 说明 | 验收 | 里程碑 |
|---|---|---|---|---|
| F1 | **Chromium 自有构建** | fork ungoogled-chromium;构建产物可复现 | 第三方能用同一命令编出**逐字节相同**的二进制 | M1 |
| F2 | **一条命令 rebase** | 跟上游 Chromium 版本(约 4 周一次);**内核版本策略**:基线取 ungoogled-chromium 当前 stable tag,滚动跟随,不做 LTS,**绝不靠改 UA 假装新版本** | 从新版本到可运行产物 ≤ 1 条命令;UA 版本号 = 内核真实版本 | M1 |
| F3 | **档案系统(三种身份)** | `real`(导入 Chrome,含扩展)/`persona`(seed 生成,持久演化)/`disposable`(一次性) | 三种都能起、都能持久化各自存储 | M3 |
| F4 | **硬隔离** | cookie / localStorage / IndexedDB / Cache / Session 目录级隔离;脚本只能拿到本档案句柄 | **跨档案读写必须失败**(对着 ego #319 做反例验收) | M3 |
| F5 | **指纹一致性引擎** | seed → 整套自洽画像(UA/平台/屏幕/缩放/GPU/字体/时区/语言/WebGL/Audio/ClientRects);**启动前交叉校验,矛盾即拒绝启动** | 100 个 seed 零矛盾;人为注入一条矛盾配置能被拦下 | M3 |
| F6 | **出口一致性自检** | 档案绑定代理;启动时校验出口 IP 地理与画像时区/语言是否自洽 | 用日本画像 + 美国出口时**拒绝启动**,而不是静默放行 | M3 |
| F7 | **进程内自动化通道** | 不暴露 TCP 调试端口;**按住 `Runtime.enable`** | 抓包证明无调试端口、无该命令;检测台 CDP 项全绿 | M4 |
| F8 | **原生语义快照** | 内核生成 a11y 树(带 `@ref`/`loc=`),不注入页面 JS(借鉴 ego MIT harness 的形状) | 跨 iframe / shadow DOM 可达;快照体积作为量化指标记录 | M2 |
| F9 | **零遥测** | 默认不发起任何遥测;可断网运行 | 断网全功能可跑;抓包零第三方上报 | M1 起持续 |
| F10 | **不限并发 + 无许可服务器** | 不做会话计数、不做激活校验 | 同时多开 N 个不被拦;无任何 license 端点 | M1 起持续 |

### 1.2 进阶层(M4–M7)

| # | 功能 | 说明 | 验收 | 里程碑 |
|---|---|---|---|---|
| F11 | **无头 + 服务器** | 同一套 API 在桌面与服务器(含容器)可用 | 服务器上跑通三种档案;与桌面 API 完全一致 | M5 |
| F12 | **内容驱动行为层** | 停留时间与内容长度相关;打字含错字-退格-重打;滚动含回滚暂停 | 停留时间与内容长度相关性 > 0.8;分布通过统计检验 | M6 |
| F13 | **代理绑定与轮换** | 按档案绑代理;支持 socks5/http;凭据不落日志 | 每档案走自己的出口;日志脱敏 | M3–M4 |
| F14 | **三种集成入口** | CLI + HTTP/WS + MCP stdio(借 ego 的形状:编排放后端,浏览器保持薄) | 三条入口都能驱动同一任务 | M5 |
| F15 | **签名发布 + 自动更新** | 正式签名、可校验、可离线安装 | 第三方可复现 + 签名可验 | M7 |
| F16 | **公开检测基准** | 定期发布主流检测站的通过率矩阵 | 可复现的分数表,不是营销话术 | M7 起持续 |

## 二、不实现的功能

### 2.1 红线类(任何情况都不做)

| # | 不做 | 理由 |
|---|---|---|
| N1 | **自动过验证码**(任何形式:打码平台、模型识别、行为绕过) | 一旦提供,项目性质从隐私工具变成规避工具;两家竞品自己都写明不做(ego 文档原文 "does not bypass them") |
| N2 | **未授权访问金融/医疗/政务认证系统** | 法律底线;AUP 明文禁止 |
| N3 | **撞库、批量注册、欺诈辅助** | 同上,且会直接招致执法关注 |
| N4 | **按站点定制的绕过规则库** | 这是灰产产品的形状。我们做通用能力,不做「针对某某站的破解包」 |
| N5 | **伪造他人身份 / 盗用他人登录态** | 档案导入仅限**本机本人的浏览器档案** |

### 2.2 战略上不做(会毁掉定位或成本失控)

| # | 不做 | 理由 |
|---|---|---|
| N6 | **桌面 GUI 管理器**(多开面板、档案卡片墙) | 那是商业反检测浏览器的形态,成本高且与「代码优先」定位冲突。v1 只有 CLI/SDK,用户用现成浏览器 UI |
| N7 | **账号体系 / 登录 / 付费墙** | 免费档无账号、无激活、无许可服务器 —— 这是对 CloakBrowser 最有效的一刀(F10) |
| N8 | **云浏览器托管服务**(浏览器即服务) | 一旦托管,我们成为处理他人流量的服务商,合规与成本都爆炸;且与「可审计、本地可控」定位相反 |
| N9 | **代理池转售** | 我们做代理**绑定能力**,不做代理供应;出口质量是用户自己的事 |
| N10 | **「保证不被封」的承诺** | 封号是多因素决策(见 §三),承诺就是骗人 |
| N11 | **卖并发数 / 卖基础指纹能力 / 卖更新** | 这正是 CloakBrowser 的盈利方式,也是它的口碑隐患 |
| N12 | **移动端** | 与核心场景无关,吃掉不成比例的工程量 |
| N13 | **Firefox 作为第一引擎** | 市场份额决定检测方优化目标;Firefox 指纹特殊反而显眼。留 F18 接口但不动手 |
| N14 | **插件市场 / site-learnings 交易市场** | 需要审核、结算、纠纷处理,是另一个产品;先只做**本地** site-learnings |

### 2.3 现在不做、留接口

| # | 不做(本轮) | 何时再做 |
|---|---|---|
| N15 | TLS/HTTP2 指纹自定义 | **浏览器内不需要**(真 Chromium 走真 TLS);只有纯 HTTP 抓取场景才需要,那时另做 |
| N16 | 团队协作(共享档案库、权限、审计日志) | 商业化阶段(变现表里的「团队」层) |
| N17 | 企业私有构建(定制补丁)、SLA、合规报告 | 商业化阶段(「企业」层) |
| N18 | 档案云同步(跨设备同一身份) | 商业化阶段(「Pro 云」层) |
| N19 | 会话录制回放 | 商业化阶段 |
| N20 | 桌面端与服务器之间的任务迁移 | M5 之后视需求 |

## 三、明确不解决的问题(必须写进用户文档,否则是骗人)

| 问题 | 为什么我们不解决 |
|---|---|
| **IP 信誉** | 机房 IP 段在大站默认降权。我们做的是「绑定与自检」,不能把机房 IP 变成住宅 IP。要过强风控,得自己上住宅代理 |
| **账号年龄 / 支付方式 / 历史行为** | 权重常常高于指纹。全新账号 + 机房 IP + 秒级操作,指纹再干净也会被封 |
| **平台风控的整体判断** | 指纹只是其中一环。我们消除「指纹这一项的嫌疑」,不能消除其它项 |
| **验证码** | 明确不做(N1)。遇到验证码就是遇到验证码 |
